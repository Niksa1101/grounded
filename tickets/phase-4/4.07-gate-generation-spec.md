**What to build:** the generation part of the gate: its contract, the normalized results schema, and spec tests.
`grounded eval gate --suite generation` works as a CLI around the Author's function.

**Read first:** Tech §15.5 (inconclusive: > 20% of cases errored for provider reasons; `n` over non-errored cases;
generation thresholds table; promptfoo's exit code ignored), Tech §15.7, PRD §8.

**Scope notes**
- G boilerplate: `schemas/eval.py` gets a normalized `GenerationRun` (per config, per case: status, metric scores,
  error type) and a parser from promptfoo's JSON output to it. Parsing a file format decides nothing, so it isn't
  Author-owned.
- Author stub: the aggregation and gating function. Its docstring states the open definitions the Author must choose:
  faithfulness as micro (over claims) or macro (over questions); how N/A enters; which error types count as "provider
  reasons".
- Spec tests: thresholds per Tech §15.5, including `≥ max(0.85, baseline − 0.05)` for faithfulness and the absolute
  `≥ 0.95` for schema validity; exactly 20% errored → not inconclusive, just above → inconclusive; inconclusive shows
  metrics with `n` but gates nothing; `n` excludes errored cases; latency p50/p95 and cost per 1k are reported, not gated.

**Acceptance criteria**
