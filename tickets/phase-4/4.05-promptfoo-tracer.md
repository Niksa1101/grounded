**What to build:** `npx promptfoo@<pinned> eval -c eval/promptfoo/promptfooconfig.yaml -j 1` runs the real pipeline
in-process for configs `no_rag` and `hybrid` over the golden set and scores the **deterministic** metrics.

**Read first:** Tech §15.3 (config, `provider.py` contract, the assertion table), 4.01 decision, `eval/README.md`.

**Scope notes**
- `eval/promptfoo/promptfooconfig.yaml`: a passthrough prompt `{{question}}`, providers `file://provider.py` labeled
  `no_rag` and `hybrid` with `config: {mode: …}`, tests from `tests_loader.py` (or the pre-step chosen in 4.01).
- `provider.py` `call_api(prompt, options, context)`: sets `APP_ENV=eval`, calls the pipeline in-process, returns
  `output` = `AskResponse` JSON, `tokenUsage`, and `metadata` (retrieved chunks **with text**, per-stage latencies,
  cost, `validation_retries`, the **pre-filter** `invalid_citation_count`). Provider errors come back as promptfoo errors
  tagged with their type, so the gate can count provider-errored cases.
- `asserts.py` (each returns `{pass, score, reason}`): schema first-try validity, citation validity, refusal
  correctness (answerable ↔ status ≠ `insufficient_context`), citation precision (the share of cited chunks matching a
  labeled section of grade ≥ 1, using `metrics.section_matches`).
- The Python side runs inside the backend's uv environment (how, per 4.01). Document the exact command.
- Results JSON goes to `eval/results/` (gitignored).
