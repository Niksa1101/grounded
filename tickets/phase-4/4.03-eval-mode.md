# 4.03 — Eval mode (`APP_ENV=eval`) and the eval LLM cache

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-4/eval-mode` · **Blocked by:** 4.02 ·
> **Builds on:** `settings.py`, `infra/kvcache.py`, 3.13 cache switch, 3.12 logging

**What to build:** one switch that makes the pipeline reproducible and quota-friendly for evals.

**Read first:** Tech §15.6 (the full list), Tech §11 (eval LLM cache key), AGENTS.md §6.5, §6.15.

**Scope notes**
- With `APP_ENV=eval`: provider list = **primary only** (fallback off, enforced at startup, not just ignored),
  temperature 0, answer cache off, rate limit and budget off (they don't exist yet; 5.04/5.05 must honor this switch,
  so note it in their tickets' tests), the SQLite embedding cache on, `request_logs.source='eval'`.
- **Eval LLM cache** `.cache/llm_eval.sqlite` via `infra/kvcache.py`: key = sha256(provider | model | temperature |
  system | user | schema hash). Store the raw text + usage. On a hit, re-validate through Pydantic exactly like a live
  response. It applies to both the generator and the judge.
- **Backoff honoring `Retry-After`** with a bounded total wait (a setting). This is allowed because it is the eval
  path, not the request path. A daily-quota 429 is raised at once and marks the case as **provider-errored** (the input
  for the inconclusive rule in 4.07).
- Cache-hit and miss counts are reported at the end of a run.

**As built** (decisions beyond the text above; the details are in Tech §11 and §15.6)
- The key also holds the output cap and the adapter settings (thinking level, reasoning effort; `params.py:adapter_params`),
  because they change the reply. A hit returns the original usage with `GenerationResult.cache_hit=True`; the pipeline
  counts hits on `RequestTrace.llm_cache_hits`, so 4.05 can leave them out of the latency percentiles.
- An entry that no longer validates is deleted and replaced by one live call. Only successful replies are stored.
- The backoff is `EVAL_MAX_TOTAL_WAIT_S` (default 120 s) and at most 3 waits per call. A quota raises the original
  `ProviderRateLimited`; a wait over the bound raises `BackoffExhaustedError` (a `ProviderRateLimited`). 4.05 reads the
  exception's class name and `is_quota`.
- `groq` as the eval generator is refused as well (the judge runs on Groq).

**Acceptance criteria**
- [x] Tests: eval settings refuse a multi-provider list; a cached response makes zero provider calls and is
      re-validated; a key change (prompt, context, model, temperature) misses; quota → a provider error with the
      right type; the bounded wait is respected (injected clock, no real sleeping in tests).

**Verify:** standard checks.

**Eval impact:** none by itself (infrastructure).
