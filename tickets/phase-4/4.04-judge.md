# 4.04 — Judge rubrics and the judge module

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** **A+G** · **Type:** Build · **Branch:** `phase-4/judge` · **Blocked by:** 4.03 ·
> **Builds on:** 4.02 Groq adapter, 4.03 cache, 3.03 prompt loader

**What to build:** versioned judge prompts and a small judge module returning structured verdicts.

**Read first:** Tech §15.3 (faithfulness per claim, correctness 0/0.5/1), Tech §15.4 (pinned model, temperature 0,
2–3 worked examples, `{verdict, reason}`), PRD FR-22.

**Scope notes**
- **The Author owns the rubric content** (what counts as SUPPORTED, what earns 0.5). The Agent drafts the structure and
  worked examples for the Author to edit. The prompt files `backend/prompts/judge_faithfulness_v1.md` and
  `judge_correctness_v1.md` are versioned by the loader.
- `evals/judge.py`: faithfulness = one call per claim with the claim + **the cited chunks' text** → `SUPPORTED |
  NOT_SUPPORTED` + reason. Correctness (a custom Python grader, not `llm-rubric`: 4.01, D50) → `0 | 0.5 | 1` + reason. Pydantic
  schemas for the verdicts, through the adapter layer and the eval cache.
- The judge model comes from `JUDGE_MODEL` and must differ in provider from the eval generator (checked at startup).

**Acceptance criteria**
- [ ] Both prompt files are approved by the Author. `prompt_version` is recorded with every verdict.
- [ ] Fake-provider tests for both judge calls, including invalid judge output (one retry, then the case is marked
      errored, not scored).

**Verify:** standard checks.

**Stop and ask:** the rubric wording (always).

**Eval impact:** defines the metrics. There is no baseline yet.
