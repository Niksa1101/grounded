### What the demonstration found

Phase 4 asked for a degraded prompt that the gate blocks. The first idea (weaken an instruction) did not work on this
model, and what worked is a format mismatch. The honest reading is in PRD §12 ("What the gate can see"): it is
sensitive to schema and format regressions, and its refusal metric moves with retrieval-induced refusals (the two false
refusals of the baseline, q016 and q026, are of that kind); a wording regression of the instructions that this model
shrugs off is invisible to it. A prompt PR therefore needs a human look at the diff as well as the gate.

### What Phase 4 deliberately did not do

- **No `eval_runs` write.** `grounded eval record` and the step in `eval.yml` exist, but the step is disabled until the
  Author sets the repository variable `EVAL_RECORD_RUNS=true` (no repository variable is set today), which waits for
  the production Neon migration in 5.09.
- **No rubric change, no second judge version, no second agreement sheet.** `judge_correctness_v2` and a sheet from a run
  with real `NOT_SUPPORTED` verdicts are open items in PRD §12.
- **No baseline, golden-set or threshold edit** after the first generation baseline (#76), and no prompt tuned against
  the golden set: `answer_v1` is as it was in Phase 3. The two false refusals (q016, q026) are measured, not fixed.
- **No required `eval` check, no path filter on the `main` trigger, no hand-over of a PR's eval cache to `main`.** Each
  is a design choice with a cost; they are open items in PRD §12.
- **No rerank (Phase 6), no fallback and no `groq` as a generator (Phase 7), no dashboard (Phase 8), no UI or deploy
  (Phase 5).** `hybrid_rerank` rows join the baseline in Phase 6.
- **The demo branch `phase-4/gate-demo` is kept**, not deleted (deleting a branch needs the Author's go, AGENTS.md §5).
  PR #86 is closed unmerged.
