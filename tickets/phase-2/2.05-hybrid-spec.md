**Scope notes**
- File `retrieval/hybrid.py`: an async `hybrid_search(conn, question, query_vector, *, index_version_id, cfg)`
  returning `list[RetrievedChunk]` with `rrf_score`, `dense_rank`, `dense_distance`, `fts_rank` set (or `None` when the
  chunk wasn't in that list). Contract docstring and `NotImplementedError`.
- The fixture needs vectors **and** words, so that the dense and lexical lists overlap only partly.
- Spec tests:
  - **RRF math**, hand-computed with `rrf_k = 60`: rank 1 in both lists → `2/61`; rank 1 in dense only → `1/61`;
    a missing rank contributes 0. Compare with `pytest.approx`.
  - **Full outer join:** a chunk found only lexically appears, with `dense_rank = None` (and the reverse).
  - Each input list is cut to `k_dense` / `k_fts` **before** fusion, and the output to `k_fused` unique chunks.
  - **Tie-break** `rrf_score DESC, chunk_id ASC`: equal scores always come back in the same order.
  - A stop-words-only question → the dense-only ranking (RRF over one list), no error.
  - Filtering by `index_version_id`. The vector is bound as a pgvector `Vector`, never formatted.
  - **Consistency oracle (allowed):** fusing the results of `dense_search` and `lexical_search` in Python gives the
    same ids and ranks as `hybrid_search`. This checks agreement between two code paths, not the SQL itself.
