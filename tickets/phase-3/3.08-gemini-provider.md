**What to build:** the real primary generator behind the `LLMProvider` contract: native structured output, usage
(including thinking tokens), typed errors, validated results.

**Read first:** Tech §9.1, 3.01 decision, `google-genai` async client docs (verified now), Tech §16 (adapter tests use
recorded fixtures).

**Scope notes**
- `generation/providers/gemini.py` uses the SDK's **async** client. The schema comes from `LLMAnswer` (converted the way
  3.01 decided), with `LLM_TEMPERATURE`, `LLM_MAX_OUTPUT_TOKENS`, `GEMINI_THINKING_LEVEL` and a per-attempt timeout
  (12 s, Tech §6) from Settings. 3.01 (D46) pinned `gemini-3.6-flash` with level `minimal`. Gemini 3.x has no token
  budget knob in the docs, so this ticket **renames** `GEMINI_THINKING_BUDGET` to `GEMINI_THINKING_LEVEL` in
  `Settings`, `.env.example` and Tech §4 (a typed value: `minimal | low | medium | high`), and the manual smoke test
  checks that `minimal` is accepted by the model. Thinking tokens come back as `thoughts_token_count` in the SDK's usage.
- **Prefactor first:** the 429/`RetryInfo`/`QuotaFailure` → `ProviderRateLimited(retry_after_s, is_quota)` mapping
  already exists in `ingest/embed.py`. Extract it into a shared helper both adapters use (a separate commit in this PR),
  so the logic isn't duplicated.
- Always Pydantic-validate the returned text, even with native schema (AGENTS.md §6.2). Validation failure →
  `ProviderBadOutput(raw, validation_error)`.
- `usage.output_tokens` includes thinking tokens (Tech §9.1, §14).
- **Fixtures:** recorded JSON responses (success, invalid output, 429 per-minute, 429 daily quota, 500) under
  `tests/fixtures/`, following the existing `tests/fixtures/gemini/` layout. The Author records them once with a real
  key using a small documented script. Tests never call the network.
- Pipeline selection: `GENERATOR_PROVIDERS[0] == "gemini"` → this adapter. Tests keep using the fake.

**Acceptance criteria**
- [ ] Adapter tests from fixtures: parsing, usage, every error mapping. The schema-conversion test passes.
- [ ] The shared error-mapping helper is used by both the embedder and the generator. Existing embed tests stay green.
- [ ] A manual smoke test (the Author runs it, it uses quota): `uv run grounded ask "How do I add a background task?"`
      returns a valid answer with real citations (output pasted in the PR).

**Verify:** standard checks, plus the smoke test.

**Stop and ask:** a new SDK dependency version bump, a model ID that differs from 3.01.

**Eval impact:** none measurable yet (Phase 4 measures it).
