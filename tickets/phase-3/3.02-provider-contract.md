# 3.02 — `LLMProvider` protocol, `FakeLLMProvider` and `LLMAnswer`

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-3/provider-contract` · **Blocked by:** 3.01 ·
> **Builds on:** `infra/provider_errors.py`

**What to build:** the provider contract every LLM adapter implements, a scriptable fake used by all tests, and the
`LLMAnswer` schema the model must return.

**Read first:** Tech §9.1 (the Protocol, `Usage`, `GenerationResult`, typed errors), Tech §9.4 (`LLMAnswer`, `LLMClaim`,
`AnswerStatus`), AGENTS.md §6.2 (always validate).

**Scope notes**
- `generation/providers/base.py`: `Usage`, `GenerationResult[T]`, the `LLMProvider` Protocol exactly as in Tech §9.1.
- `generation/providers/fake.py`: `FakeLLMProvider` returns scripted results or raises scripted typed errors **in
  order**, and records every call (`system`, `user`, schema, temperature) so tests can assert retry feedback.
  "Invalid JSON" is scripted as raw text that fails validation, surfaced as `ProviderBadOutput`, just like a real adapter.
- `schemas/llm.py`: `LLMAnswer`, `LLMClaim`, `AnswerStatus` per Tech §9.4. `citation_ids` items must match `^c[1-9]$`
  (Pydantic-enforced).
- **Schema simplicity test:** the JSON schema of `LLMAnswer` has no `anyOf`/`oneOf`/`allOf`, no nullable types, no
  recursion, and enums are string literals (Tech §9.1). The nested `LLMClaim` appears as one local, non-recursive
  `$ref` into `$defs`; an adapter that needs it inlined does that in its own schema conversion (3.08). This keeps
  both providers able to use it.
- `ProviderBadOutput` today takes `raw`. Tech §9.1 also names `validation_error`. Add it if the retry feedback needs it
  (it does in 3.07).

**Acceptance criteria**
- [x] Protocol, result types, fake and `LLMAnswer` with unit tests (validation edge cases: bad label, too many claims,
      empty text, out-of-range `self_confidence`).
- [x] The schema-simplicity test passes.
- [x] The Author reviewed `LLMAnswer` closely (PRD §9 marks it "Author reviews closely").

**Verify:** standard checks.

**Stop and ask:** any deviation from Tech §9.4 field names or limits (schema contract).

**Eval impact:** none.
