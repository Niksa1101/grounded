# 3.07 — Output validation with one retry and error feedback

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-3/validation-retry` · **Blocked by:** 3.06 ·
> **Builds on:** 3.02 fake, 3.06 semantic checks

**What to build:** when the model's output is invalid (Pydantic or semantic), the pipeline retries **exactly once** on
the same provider with the error appended to the user message. If the retry fails too, the answer is a
`502 validation_failed`.

**Read first:** Tech §9.5 (steps 1, 3, 5), AGENTS.md §6.4 (exactly one retry, no loops, no sleeping), the Phase 3 note in the
[phase README](README.md).

**Scope notes**
- The feedback text follows Tech §9.5 ("Your previous output was invalid because …") and is part of the prompt
  contract. Where it lives (prompt file vs code) affects `prompt_version`. Put it in the prompt file so it is versioned,
  or explain why not. **Decided by the Author (option B):** an optional `# Retry feedback` section in `answer_v1.md`
  with `{{error}}`, parsed by `prompts.py`, rendered with `Prompt.render_retry`. The wording is Tech §9.5's, verbatim.
  The `answer_v1` hash changed once, by the Author's approval (no baseline references it yet).
- `validation_retries` is counted and exposed to logging (3.12).
- No fallback yet. Provider errors other than bad output (429/5xx/timeout) map to `503 provider_unavailable` with
  `Retry-After` when known.

**Acceptance criteria**
- [x] Fake-provider tests: invalid JSON → retry → success; zero valid citations → retry → success; invalid twice →
      502 `validation_failed`; the retry's user message contains the validation error; exactly two provider calls, never three.
- [x] 429 from the fake → 503 with `Retry-After`.

**Verify:** standard checks.

**Stop and ask:** the location of the feedback text (prompt versioning). *Answered, see the scope notes.*

**Eval impact:** none measurable yet.
