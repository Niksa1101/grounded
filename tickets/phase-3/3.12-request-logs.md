# 3.12 — Request logging, stage timing and shadow cost

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-3/request-logs` · **Blocked by:** 3.11 ·
> **Builds on:** `infra/logging.py`, 3.01 `pricing.toml`, DB §4 `request_logs`

**What to build:** every `/v1/ask` request, whatever its outcome, writes one `request_logs` row with stage latencies,
tokens, versions and shadow cost. The response `meta` carries the same numbers (the 3.05 placeholders are removed).

**Read first:** Tech §14 (logs, stage timing, `pricing.toml`, cost formula), DB §4 (`request_logs` columns and the
`outcome` CHECK list), Tech §6 (stage names), AGENTS.md §6.9, §6.13.

**Scope notes**
- `infra/timing.py`: a `stage("embed" | "retrieval" | "rerank" | "llm")` context manager on the monotonic clock. The
  total includes the cache lookup and logging. Tests use an injected clock (no wall-clock reliance, AGENTS.md §8).
- `observability/cost.py`: loads `pricing.toml` (validated with Pydantic) and computes the Tech §14 formula. Thinking
  tokens count as output. An unknown model → an explicit error at startup, not a silent 0.
- `observability/request_log.py`: inserts the row, with `question_hash` = sha256(normalized question). `question` is
  stored (retention job in 5.11). `ip_hash` stays NULL until 5.03. `source='api'` (5.03 sets `'web'` behind the proxy).
- Records `prompt_version`, `index_version_id`, `retrieval_config_hash`, `validation_retries`,
  `invalid_citation_count`, `citation_count`, `min_claim_confidence`, `error_code`.
- A failed log write is logged at ERROR with the `request_id` and never breaks the response. It is never silent either.
- **Never** log question text to stdout: add a test that captures logs for a request and asserts the question is absent.

**Acceptance criteria**
- [ ] Integration tests: one row per outcome (`answered`, `insufficient_context`, `bad_request`, `validation_failed`,
      `provider_unavailable`, `internal_error`) with correct fields.
- [ ] Cost unit tests with hand-computed values. `meta.latency_ms` has total/embed/retrieval/llm, and `meta.tokens`
      and `meta.shadow_cost_usd` are real.
- [ ] The no-question-text-in-stdout test passes.

**Verify:** standard checks, then run a local request and `SELECT outcome, latency_total_ms, shadow_cost_usd FROM
request_logs ORDER BY created_at DESC LIMIT 5`.

**Eval impact:** none.
