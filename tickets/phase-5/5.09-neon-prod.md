**What to build:** production Neon has the schema, a least-privilege `app` role, and an active index, all produced by
repeatable, reviewed steps.

**Read first:** DB §2 (Neon notes: pooled vs direct), DB §5 (roles and grants), DB §10 (production migrations from CI
or locally with the direct URL, never from the runtime), Tech §17 (`ingest.yml`), Tech §18 "Database — Neon".

**Scope notes**
- `ingest.yml`: `workflow_dispatch(ref, activate)` → migrate + ingest into Neon with `DATABASE_URL_DIRECT`. It prints
  the index stats. It **restores the embedding cache** (without it, a full ingest takes two days of quota).
- The `app` role and grants (DB §5) come from a documented one-time runbook, since the password comes from a secret
  manager, not from a migration. The Author runs it.
- The runbook covers: create the role, set Vercel's `DATABASE_URL` to the pooled URL as `app`, run the workflow, check
  `grounded index list`.

**Acceptance criteria**
- [ ] The workflow is merged. The Author ran it, and the index is active on Neon (stats pasted in the PR or a follow-up).
- [ ] `app` can read the index and write logs/cache/budget, but can't modify the index (a manual check listed in the runbook).

**Stop and ask:** every production action (the Author runs them).
