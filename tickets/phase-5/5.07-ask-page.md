**What to build:** the full FR-26 ask experience: cited answers you can verify, honest states, a debug row, a privacy
notice, and everything keyboard-accessible.

**Read first:** PRD FR-26, NFR-9, UC5; Tech §19 (states, rendering, debug row, accessibility); Tech §12 (output rendering).

**Scope notes**
- `[n]` markers become **buttons** that focus or open the matching source card. Source cards show the breadcrumb, the
  snippet and an external link to the exact anchor.
- Status badge (`answered`, `partial`, `insufficient_context`). Claims with confidence < 0.5 get a subtle indicator
  whose explanation ("heuristic") is reachable **without hover** (focusable or visible text).
- States: idle · loading, which after 5 s says "Waking up the free-tier backend…" · answered/partial ·
  `insufficient_context` (with follow-up suggestions) · `rate_limited` with a countdown from `retry_after_s` ·
  `budget_exhausted` (friendly) · error, showing the `request_id`.
- A collapsible debug row: stage latencies, tokens, provider/model, fallback/cache/rerank flags, shadow cost,
  prompt/index version.
- The privacy notice under the input (free AI APIs are used; don't enter personal data). Code highlighting in answers.
- shadcn/ui components. Contrast and focus states checked.

**Acceptance criteria**
- [ ] Every state is reachable and demonstrated locally (fake backend responses are fine), with screenshots in the PR.
- [ ] Keyboard-only walkthrough: ask → open a citation → expand debug, with no mouse.
- [ ] Frontend checks green.

**Verify:** frontend standard checks, plus a manual run.

**Eval impact:** none.
