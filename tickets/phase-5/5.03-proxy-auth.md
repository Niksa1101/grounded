# 5.03 — Proxy secret, trusted client IP and IP hashing

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-5/proxy-auth` · **Blocked by:** 5.02 ·
> **Builds on:** 3.05 routes, 3.12 logging, `settings.py` prod checks

**What to build:** `/v1/*` accepts traffic only from the frontend proxy. The real client IP comes from the proxy and
is HMAC-hashed at once. The raw IP never reaches a log or a row.

**Read first:** Tech §12 (proxy secret, client IP rules), PRD FR-18, NFR-4, NFR-7, AGENTS.md §6.13.

**Scope notes**
- `api/security.py`: `X-Proxy-Secret` compared in constant time (`hmac.compare_digest`) → 401 `unauthorized` in the
  shared error shape. The `ALLOW_DIRECT_API=true` bypass works in dev only (prod already refuses it, `settings.py`).
  `/healthz` and `/readyz` stay public.
- Client IP: `X-Client-IP` is trusted **only** with a valid secret, otherwise the socket peer. It is HMAC-SHA256 hashed
  with `IP_HASH_SECRET` immediately (`infra/hashing.py`), and the raw value is dropped.
- `request_logs.ip_hash` is filled. `source='web'` when it came through the proxy, `'api'` otherwise.
- The uvicorn access log stays off (it prints raw IPs; `grounded serve` already does this). Check that the Vercel
  runtime doesn't log it either, and note the result.

**Acceptance criteria**
- [ ] Tests: missing or wrong secret → 401; correct → 200; `X-Client-IP` ignored without the secret; the stored
      `ip_hash` equals the HMAC; captured logs contain **no raw IP** for any request.
