> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-5/budget` · **Blocked by:** 5.04 ·
> **Builds on:** DB §7.1 SQL, 3.12 logging, 3.13 cache ordering

**What to build:** each LLM call first reserves one unit of a global daily budget. When the budget is gone, the demo
answers `503 budget_exhausted` (the UI shows a friendly state), and cache hits never consume budget.

**Read first:** DB §7.1 (atomic reserve; no row = exhausted; tokens added afterwards), Tech §12 (global budget),
PRD FR-16.

**Scope notes**
- `infra/budget.py` with the exact DB §7.1 pattern (UTC day, `ON CONFLICT … WHERE llm_calls < limit RETURNING`).
- A **retry is another LLM call**, so it reserves again. Token totals are added after each call.
- **Advisory check (5.01):** after the answer-cache lookup and **before the embed stage**, one plain `SELECT` of today's
  `llm_calls` (DB §7.1, "Advisory check") refuses the request with `budget_exhausted` when it has reached
  `DAILY_LLM_BUDGET`, so an exhausted day spends no query embedding. It reserves nothing; the atomic reserve before the
  LLM call stays the only thing that enforces the cap. Update the pipeline order in Tech §1 if the code differs.
- `DAILY_LLM_BUDGET` unset → no cap in dev and test, and **required when `APP_ENV=prod`** (5.01): `_check_prod` in
  `settings.py` names it as missing, like the other prod secrets (explicitly set, not blank). Demo value `300`.
  **Eval bypasses the
  budget:** with `settings.app_env == "eval"` nothing is reserved and `daily_usage` is not touched (Tech §15.6; 4.03
  added the switch and `tests/support.py:EVAL_SETTINGS`), so the LLM calls of an eval run neither use up the demo's
  daily budget nor end in `budget_exhausted`.

**Acceptance criteria**
- [x] Integration test for **atomicity under concurrency**: N parallel reserves at `limit − 1` → exactly one succeeds.
- [x] Tests: exhausted → 503 `budget_exhausted` with the outcome logged; a cache hit doesn't touch `daily_usage`; the
      tokens are accumulated.
- [x] Tests: with the budget used up, the embedder is **not called** (a fake embedder counts its calls) and the
      response is `budget_exhausted`; a cache hit is still served on an exhausted day. `APP_ENV=prod` without an
      explicit `DAILY_LLM_BUDGET` fails settings validation.
- [x] **Eval switch test:** with `EVAL_SETTINGS` (`APP_ENV=eval`) and a budget of 1, two LLM calls both go through and
      `daily_usage` has no row; the same two calls under `APP_ENV=test` end in `budget_exhausted` on the second.
