# 5.05 — Global daily LLM budget

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** G · **Type:** Build · **Branch:** `phase-5/budget` · **Blocked by:** 5.04 ·
> **Builds on:** DB §7.1 SQL, 3.12 logging, 3.13 cache ordering

**What to build:** each LLM call first reserves one unit of a global daily budget. When the budget is gone, the demo
answers `503 budget_exhausted` (the UI shows a friendly state), and cache hits never consume budget.

**Read first:** DB §7.1 (atomic reserve; no row = exhausted; tokens added afterwards), Tech §12 (global budget),
PRD FR-16.

**Scope notes**
- `infra/budget.py` with the exact DB §7.1 pattern (UTC day, `ON CONFLICT … WHERE llm_calls < limit RETURNING`).
- A **retry is another LLM call**, so it reserves again. Token totals are added after each call.
- `DAILY_LLM_BUDGET` unset → per the 5.01 decision (e.g. required in prod, unlimited in dev). **Eval bypasses the
  budget:** with `settings.app_env == "eval"` nothing is reserved and `daily_usage` is not touched (Tech §15.6; 4.03
  added the switch and `tests/support.py:EVAL_SETTINGS`), so the LLM calls of an eval run neither use up the demo's
  daily budget nor end in `budget_exhausted`.

**Acceptance criteria**
- [ ] Integration test for **atomicity under concurrency**: N parallel reserves at `limit − 1` → exactly one succeeds.
- [ ] Tests: exhausted → 503 `budget_exhausted` with the outcome logged; a cache hit doesn't touch `daily_usage`; the
      tokens are accumulated.
- [ ] **Eval switch test:** with `EVAL_SETTINGS` (`APP_ENV=eval`) and a budget of 1, two LLM calls both go through and
      `daily_usage` has no row; the same two calls under `APP_ENV=test` end in `budget_exhausted` on the second.

**Verify:** standard checks.

**Eval impact:** none.
