> **Owner:** **D** · **Type:** Decision · **Branch:** `phase-5/decision-deploy` · **Blocked by:** 5.01

**Question:** which Vercel function region, `maxDuration` values and timeout chain do the frontend and backend use?

**Facts to verify (current Vercel Hobby docs, dated):** the max function duration, the region list and the one closest
to Neon AWS US East 2 (Ohio), the Python bundle limit, lifespan support and the shutdown budget, the monthly
allotments (Tech §18 has a 2026-09-24 snapshot; re-verify).

**The timeout chain to fix in writing:** per-stage timeouts (Tech §6) < `REQUEST_DEADLINE_S` (25 s) < the proxy's fetch
timeout < the frontend route's `maxDuration`. The backend's cold start must fit, or the UI shows a retry state
(Tech §18).

**Deliverables:** PRD §12 region item resolved, Tech §18 updated with the chosen values and the verification date.

**Acceptance criteria**
- [x] Memo with verified facts. Author decision recorded.

**Decision (Author, 2026-10-11)** — recorded in PRD D53 and PRD §12 (region item); the verified facts and the chain are in Tech §18; the memo with the options and sources is in the PR description.
- **Region:** `cle1` (Cleveland, AWS `us-east-2`) for both projects, the same AWS region as Neon. Rejected: `cle1` backend with the default `iad1` frontend (the frontend→backend hop would cross regions), `iad1` for both (every DB round trip crosses `us-east-1` → `us-east-2`).
- **Timeout chain (s):** stages (3 / 2 / 3 / 12 per LLM attempt) < `REQUEST_DEADLINE_S` 25 < backend `maxDuration` 30 < proxy fetch 35 < frontend ask route `maxDuration` 40. Hobby caps `maxDuration` at 300 s, so these are choices. Rejected: backend 60 s or the 300 s default (a stuck request holds an instance longer), proxy 30 s (5 s for a cold start) and 60 s (a broken request can make the user wait a minute).
- **Gap found:** `REQUEST_DEADLINE_S` is a `Settings` field that no code enforces, nor is the 2 s retrieval stage timeout; the `deadline_exceeded` code exists only in the API schema. Decided: ticket 5.08 adds both, so the chain holds.
- **Follow-ups written into the tickets:** 5.06 (proxy values), 5.08 (deadline, `maxDuration` entry, region, pool close within 500 ms), 5.10 (cold start budget of 10 s).

**Eval impact:** none.
