**What to build:** the backend can be deployed as its own Vercel project (root `backend/`) and starts correctly there.

**Read first:** Tech §18 "Backend — Vercel Functions" (entry module, `[tool.vercel] entrypoint`, no import-time side
effects, region, preview deployments without production secrets), DB §2 (pooled URL; `prepare_threshold=None` if the
pooler complains).

**Scope notes**
- A thin entry module with `app = create_app()`, referenced from `pyproject.toml`. `grounded.main` stays free of
  import-time side effects (a test can check this).
- Region and durations per 5.02 (D53): `vercel.json` with `"regions": ["cle1"]` and a `functions` entry with `"maxDuration": 30`, keyed on the **resolved entrypoint file** (the Vercel docs key Python framework apps on it, e.g. `app/main.py`, not on the `module:app` string; confirm which file the `[tool.vercel] entrypoint` resolves to). The bundle excludes tests, fixtures and dev dependencies (`excludeFiles`); check the size against the 500 MB limit.
- **Enforce the deadline (added by 5.02).** `REQUEST_DEADLINE_S` (25 s) and the retrieval stage timeout (2 s, Tech §6) are not enforced by any code today. The `/v1/ask` route (or the pipeline) wraps the request in `asyncio.timeout(settings.request_deadline_s)` and answers with the 504 `deadline_exceeded` of Tech §13, with `request_id`, a `request_logs` row and the stage timings so far; the retrieval query gets its own timeout. Tests use a fake slow provider and a short deadline, no wall-clock sleeps beyond a few milliseconds. The timeout chain is Tech §18; the new settings, if any, go in `.env.example`. Whether the deadline also bounds the `cache` lookup and the budget reserve is yours to decide and to write down.
- Shutdown: Vercel allows 500 ms after SIGTERM and shows no shutdown logs (Tech §18), so the lifespan closes the pool with a short timeout and does not rely on a log line to prove it ran.
- The lifespan on Vercel: pool open, the active index loaded, providers created lazily. `/readyz` reflects readiness.
- Settings `APP_ENV=prod` refuse to start without the required secrets (already enforced; 5.01 decided that
  `DAILY_LLM_BUDGET` is required too, and 5.05 adds it to the check). Confirm here that the prod env list in Tech §18
  matches what `_check_prod` demands.
- Path assumptions that break in an installed bundle (review notes): `importlib.metadata.version("grounded")` needs the
  installed package metadata, and `_REPO_ROOT` (`settings.py`), `DEFAULT_MIGRATIONS_DIR` and `GOLDEN_DIR` depend on the
  source-tree layout. None of them may be needed by the request path on Vercel; check each one, and fail soft or
  read from a bundled location. (`/readyz` is covered in 3.05, and `prepare_threshold` in this ticket's DB note.)
- Verifying the build needs the Vercel CLI or a preview deploy. Either is a new tool or an outward action → **ask the
  Author** which one.

**Acceptance criteria**

- [ ] The deadline is enforced: a test shows a request that outlives `REQUEST_DEADLINE_S` ends as 504 `deadline_exceeded` with a `request_id`, and the stage timeout for retrieval fails that stage.
