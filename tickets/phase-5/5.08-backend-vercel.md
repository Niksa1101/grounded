**What to build:** the backend can be deployed as its own Vercel project (root `backend/`) and starts correctly there.

**Read first:** Tech §18 "Backend — Vercel Functions" (entry module, `[tool.vercel] entrypoint`, no import-time side
effects, region, preview deployments without production secrets), DB §2 (pooled URL; `prepare_threshold=None` if the
pooler complains).

**Scope notes**
- A thin entry module with `app = create_app()`, referenced from `pyproject.toml`. `grounded.main` stays free of
  import-time side effects (a test can check this).
- Region per 5.02. The bundle excludes tests, fixtures and dev dependencies; check the size against the limit.
- The lifespan on Vercel: pool open, the active index loaded, providers created lazily. `/readyz` reflects readiness.
- Settings `APP_ENV=prod` refuse to start without the required secrets (already enforced; add `DAILY_LLM_BUDGET` if 5.01
  said so).
- Path assumptions that break in an installed bundle (review notes): `importlib.metadata.version("grounded")` needs the
  installed package metadata, and `_REPO_ROOT` (`settings.py`), `DEFAULT_MIGRATIONS_DIR` and `GOLDEN_DIR` depend on the
  source-tree layout. None of them may be needed by the request path on Vercel; check each one, and fail soft or
  read from a bundled location. (`/readyz` is covered in 3.05, and `prepare_threshold` in this ticket's DB note.)
- Verifying the build needs the Vercel CLI or a preview deploy. Either is a new tool or an outward action → **ask the
  Author** which one.

      DB, as expected).
- [ ] Documented deploy settings (root, entrypoint, region) in Tech §18.
