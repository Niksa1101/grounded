**Scope notes**
- Retrieval eval: `hybrid_rerank` = hybrid → rerank of the top `K_FUSED` → metrics over the reranked list (state which
  `k` MRR uses). The adapter returns the whole reranked list (Tech §8: no `top_n` is sent), so `recall@10` and MRR are
  computed over the same 40 candidates as for `hybrid`.
- promptfoo: a `hybrid_rerank` provider label. `eval.yml` runs `eval/promptfoo/promptfooconfig.yaml` as a whole, so the
  third provider must not end up in that file's run: put it in a second config file (or behind a switch that is off by
  default) that only the manual command uses, and show in the PR that the file `eval.yml` runs is unchanged.
- Run `hybrid_rerank` by hand with `RERANK_PROVIDER=cohere` and `RERANK_MODEL=rerank-v4.0-pro` in `.env` (Tech §8):
  `uv run grounded eval retrieval --config hybrid_rerank`. The Trial key allows **10 Rerank requests a minute**, so the
  runner paces its uncached calls (at least 6 s apart; 30 questions take about 3 minutes) and stops on a 429 instead of
  looping. The same timeout `RERANK_TIMEOUT_S` applies: a run in which any question degraded to the RRF order is not a
  result and is never written to a baseline. The rerank cache makes a re-run free; the whole phase has 150 real calls.
- Real calls need `COHERE_API_KEY` (and, for the generation run, `GEMINI_API_KEY` and `GROQ_API_KEY`) in the root `.env`;
  a missing key is a blocker to report, not something to work around. The first real call also settles whether the Trial
  key accepts `rerank-v4.0-pro` (unverified in 6.01); if it does not, use the fallback `rerank-v4.0-fast` (priced already)
  and say so in the PR. Log the stage's p50 and p95 latency (`latency_rerank_ms`) for the lift analysis.
- Baseline PR `eval: update baseline (add hybrid_rerank rows)` for both files, with before/after tables and `n`. The
  conditions the Author set for it (2026-10-12): only **add** `hybrid_rerank` rows; every existing row and every
  threshold stays byte-identical (prove it with `git diff`); the numbers come only from the tool run
  (`--write-baseline` / `grounded eval baseline`), never typed; an `inconclusive` or rerank-degraded run is never
  written; the new rows have no thresholds.
