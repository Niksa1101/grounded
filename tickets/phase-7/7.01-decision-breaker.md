# 7.01 — Decision: breaker state on serverless, quota reset, breaker timings

> **Before you start:** read [AGENTS.md](../../AGENTS.md), the rules in [tickets/README.md](../README.md) (how to work a ticket, ticket types, [standard checks](../README.md#standard-checks)) and the phase notes in [README.md](README.md). Work only on this ticket.

> **Owner:** **D** · **Type:** Decision · **Branch:** `phase-7/decision-breaker` · **Blocked by:** 6.05

**Question:** on Vercel, breaker state in memory is per instance (PRD §12). Is a per-instance breaker accepted, or does
the state go to Postgres? And which timings are used?

**Facts and inputs:** how many instances run at demo traffic (from 5.10 observations and Vercel docs); the Gemini
daily-quota reset (midnight Pacific, Tech §5.6) and Groq's reset rule; the Tech §10 defaults (per-minute open = 
`Retry-After` or 60 s; quota → until reset or 15 min then half-open; 3 failures in 60 s → open 30 s).

**Deliverables:** PRD §12 item resolved (a D row), Tech §10 updated, the breaker timings as `Settings` fields in
`.env.example`.

**Acceptance criteria**
- [x] Memo. Author decision recorded. (The memo is the description of
      [#124](https://github.com/Niksa1101/grounded/pull/124). The Author decided (a) to (d) below on 2026-10-14 and
      delegated the research and the wording to the Agent, as for D55, so it is recorded as PRD D57 with the Author able
      to confirm or veto it, and the cap, the one choice the Agent made. Unverified facts are listed in PRD §12 "Phase 7
      decision (7.01)".)

**Decision (Author, 2026-10-14; research and wording by the Agent)** — recorded in PRD D57 and PRD §12, rules in Tech §10.
- **(a) Breaker state:** per instance, in memory, per provider; no table, no migration. Lost on a cold start, not shared
  between instances; a burst can send each instance a few calls to a failing provider.
- **(b) Timings:** the Tech §10 defaults, as `Settings` fields (done in this PR, `.env.example` and Tech §4 updated):
  `BREAKER_RATE_LIMIT_OPEN_S=60`, `BREAKER_QUOTA_OPEN_S=900`, `BREAKER_FAILURE_THRESHOLD=3`,
  `BREAKER_FAILURE_WINDOW_S=60`, `BREAKER_FAILURE_OPEN_S=30`, plus the Agent's `BREAKER_MAX_RETRY_AFTER_S=3600` (a cap on a
  provider-supplied wait). Quota reset: Gemini the next midnight Pacific, Groq its own `retry-after`, else 900 s.
- **(c) Fallback answers are not cached** in the answer cache (key and schema unchanged); moving `thinking_level` and
  `GROQ_REASONING_EFFORT` into the providers stays open.
- **(d) A fallback that cannot be built** is skipped with a logged WARNING; startup fails only when the first entry cannot
  be built. Eval mode is unchanged.
- **Follow-ups written into the tickets:** 7.02 (settings-driven timings, the reset derivation and its test cases),
  7.04 (skip an unbuildable fallback, do not cache a fallback answer, one Gemini attempt, the first-entry rule).

**Eval impact:** none.
