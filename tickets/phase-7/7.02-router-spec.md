**Scope notes**
- `generation/router.py`: `ProviderRouter.generate(...) -> GenerationResult`, `AllProvidersUnavailable(retry_after)`,
  an attempt record (provider, outcome, latency), the breaker state types. Stub with `NotImplementedError`.
- An **injected clock**, so breaker timing is testable without sleeping (AGENTS.md §8).
- One test per row of the Tech §10 table: success resets; bad output → 1 retry with feedback → next provider; 429 with
  and without `Retry-After`; quota; 3 timeouts in 60 s → open 30 s; breaker open → skipped without a call; half-open
  allows **exactly one** trial under concurrent requests; all open → `AllProvidersUnavailable` with the minimum
  remaining time; eval mode → primary only; the router reports `fallback_used`, `provider`, `model`, attempts.
- The router never sleeps and never waits out a `Retry-After`.
- **From 7.01 (PRD D57, Tech §10 "Decided in 7.01"):**
  - The timings are not literals: the router is built from the `BREAKER_*` `Settings` fields (Tech §4). A provider-supplied
    wait is `min(retry_after_s, BREAKER_MAX_RETRY_AFTER_S)`; a `retry_after_s` of zero or less counts as absent.
  - The reset of a daily quota is a pure function of the provider name, the injected wall clock and `retry_after_s`,
    returning seconds or `None`: Gemini the next midnight in `America/Los_Angeles` (cases for both daylight-saving
    change-over days, and for a zone that cannot be loaded: `None` and a logged warning), Groq its `retry_after_s` cut to
    the cap, anything else `None` (then `BREAKER_QUOTA_OPEN_S`). The breaker state is in memory per instance, so the tests
    need no database.
  - Every open and every skip is logged (provider, reason, seconds, how derived; never a question).
  - Decide how the router learns the time left before the request deadline, so it does not start an attempt that cannot
    finish (one attempt may take 12 s, the deadline is 25 s; PRD §12).
