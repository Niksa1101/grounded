**What to build:** `/v1/ask` generates through the router over `GENERATOR_PROVIDERS`. The single-provider retry from
3.07 moves into the router. Fallback shows up in `meta` and `request_logs`, and the phase closes with a demonstration.

**Read first:** Tech §10, Tech §13 (503 `provider_unavailable` + `Retry-After`), DB §4 (`fallback_used`, `provider`,
`model`, `validation_retries`), PRD FR-15.

**Scope notes**
- Remove the pipeline-level retry (no double retry). The 3.07 tests move or adapt so the behavior stays covered.
- Each fallback call also reserves budget (5.05).
- **From 7.01 (PRD D57):**
  - **A fallback answer is not stored in the answer cache** (`fallback_used` true → no write; the key and the schema do
    not change). Test: a fallback answer leaves no row, a primary answer does, and a cached answer is still served while
    the primary's breaker is open.
  - **An unbuildable fallback is skipped** at startup with a logged WARNING that names the missing variable
    (`GROQ_API_KEY`, `GROQ_MODEL`); startup fails only when the first entry cannot be built. Eval mode is unchanged.
  - **The Gemini client makes one attempt**, set explicitly (`google-genai` 2.25.0 retries nothing by default, but
    Google's docs say its SDKs retry a 429 or 5xx up to four times, which would sleep in the request path and hide a 429
    from the router). A test pins it.
  - **First entry other than `gemini` or `fake`:** outside eval mode it is refused at startup, or the adapter parameters
    (`thinking_level`, `GROQ_REASONING_EFFORT`) move into the providers and the cache key (PRD §12). Ask the Author which.
- **From 7.02 (Tech §10 "Contract (7.02)"):** the router takes hooks, no pipeline import. `before_call` is the budget
  reserve (every call), `validate` runs `map_citations`, sets the trace's citation counts, keeps the `MappedAnswer` and
  returns its `bad_output`, `retry_user` is `Prompt.render_retry`, `on_attempt` records the usage and `cache_hit` of every
  call (`validation_retries` = the attempts with `is_retry`), `time_left` is the time left before `REQUEST_DEADLINE_S`,
  `timeout_s` is `Settings.call_timeout_s`. `meta.provider`, `model` and `fallback_used` come from `RoutedGeneration`.
  Error handlers: `AllProvidersUnavailable` is a `ProviderError` with no handler yet (unhandled it would be a 500),
  `RouterDeadlineError` → 504 `deadline_exceeded` (outcome `deadline_exceeded`, like `RetrievalTimeoutError`),
  `ProviderBadOutput` stays 502, `ProviderRequestRejected` stays an unhandled, loud 500.
- `AllProvidersUnavailable` → 503 with `Retry-After`, outcome `provider_unavailable`.
- Eval mode stays primary-only (a startup check from 4.03).
- **Demo:** a service test and a documented local run with a fake Gemini returning 429 → Groq answers, the next request
  skips Gemini while the breaker is open, and the logs show `fallback_used=true`.
- Closeout: exit criteria, README "resilience" note, roadmap, PRD status.
- **From the 7.03 review (PR #126; the router already supports all of it):**
  1. In eval mode (`APP_ENV=eval`) build the router with `breakers_enabled=False` and unwrap
     `AllProvidersUnavailable.causes[-1]` (re-raise it) so `ask_batch`, `promptfoo_provider` and the gate see the
     same typed errors as before (`ProviderRateLimited`, `BackoffExhaustedError`, `is_quota`, `retry_after_s`). A
     breaker would skip every golden question after one 429 and hide the quota from the eval's own backoff.
  2. Pass the request's `request_id` through `generate(log_extra={"request_id": ...})`: it reaches every router
     log line (a clashing key is a `LogExtraError`).
  3. The `validate` and `retry_user` closures must be pure and never raise. If one does, the error propagates
     unchanged and the usage of that one call is not reported.
  4. Register the handlers: 503 `provider_unavailable` for `AllProvidersUnavailable` (send `Retry-After` from
     `retry_after_s` only when it is not `None`) and 504 `deadline_exceeded` for `RouterDeadlineError`.
  5. Regression notes for the PR description: `time_left() >= timeout_s` makes a request that reaches the LLM stage
     after 13 s of the 25 s deadline a 504 (this matches D53); `validation_retries` becomes the number of retry
     attempts across providers; the old INFO line "model output invalid, retrying once" disappears (the router
     logs every failed call now); a rejected request (a bad key) on the primary burns one budget unit per request,
     because the reserve comes before the doomed call.
